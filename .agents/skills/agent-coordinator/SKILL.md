# هماهنگی Agentها

برای واگذاری کار مستقل به Agent متخصص، مدیریت نتیجه و ادامه پس از تصمیم کاربر استفاده کن. [روال واگذاری](../../../system/DELEGATION.ReadOnly.md) را بخوان و نقش مناسب را از [نقش‌ها](../../../system/AGENT-ROLES.ReadOnly.md) انتخاب کن. مدیریت وضعیت تسک تابع مهارت [task-companion](../task-companion/SKILL.md) است.

- پیش از واگذاری، Agent اصلی هدف، منابع، انتخاب‌های مستقل و تصمیم‌های محفوظ را با کاربر روشن و مدرک اختیار را در قرارداد ثبت کند. پاسخ معلوم را دوباره نپرس؛ خواستهٔ روشن و تصمیم‌های قبلی همان مأموریت می‌توانند مدرک اختیار باشند. ابهام مؤثر را از طریق Agent اصلی بپرس. تأیید یک مأموریت مجوز دائمی نیست.
- نمایه‌ها در `data/work/` و `data/personal/` مستقل‌اند. مأموریت تازه از قالب‌های روال ساخته می‌شود؛ دادهٔ واقعی در فایل ثابت یا محیط دیگر قرار نگیرد. Agent فرعی حق ویرایش TASKS، STEPS، HISTORY، MEMORY، نمایه‌ها، قرارداد یا قواعد ثابت را ندارد؛ فقط فایل نتیجهٔ مشخص‌شده را می‌نویسد.
- اگر ابزار `collaboration.spawn_agent` در دسترس است، Agent اصلی قرارداد آماده را به آن بدهد. نام نقش، مسیر قرارداد، نسخه، شمارهٔ تلاش، منابع مجاز و مسیر نتیجه را در پیام بیاور. برای جلوگیری از انتقال زمینهٔ نامرتبط، `fork_turns="none"` و زمینهٔ لازم در قرارداد/پیام مناسب است. مدل/سطح استدلال را بدون درخواست یا قاعدهٔ صریح تعیین نکن. ابزارهای collaboration مستقیم فراخوانی می‌شوند، نه داخل functions.exec.
- شناسهٔ واقعی برگشتی ابزار و زمان آغاز را ثبت کن؛ پیش از آغاز موفق، «در حال اجرا» ننویس. برای ادامه از `collaboration.followup_task` یا ابزار معادل موجود استفاده کن و قرارداد نسخهٔ تازه/تصمیم را بده. برای پیگیری، پیام‌ها و نتیجهٔ ابزار را بخوان؛ از گزارش شکست، پایان یا نیاز به تصمیم وضعیت درست بساز. شناسهٔ قبلی ممکن است در نشست تازه نامعتبر باشد؛ ابتدا وضعیت را بررسی کن و در صورت نیاز تلاش تازه با فایل نتیجهٔ تازه ایجاد کن.
- اجرای هم‌زمان فقط برای مأموریت‌های مستقل و فایل‌های نتیجهٔ متفاوت است. اگر ابزار واگذاری موجود نیست، همان مأموریت را مستقیم در نقش مربوط انجام بده و شیوهٔ اجرا را صریح ثبت کن؛ اجرای پس‌زمینهٔ انجام‌نشده را گزارش نکن. این مهارت اجراکنندهٔ دوره‌ای نیست.
- در پیام واگذاری، خواندن `AGENTS.md` و قواعد ثابتِ مرتبط را صریح بخواه؛ لحن رسمی و تفکیک منابع از دستورها الزامی است. Agent فرعی بدون مجوز مشخص در قرارداد، Agent دیگری ایجاد نکند. محدودیت نوشتن یک قاعدهٔ همکاری است؛ این ساختار به‌تنهایی جداسازی فنی دسترسی فایل‌ها ایجاد نمی‌کند.
- Agent فرعی هنگام برخورد با تصمیم تازه، بستهٔ تصمیم را در نتیجه و پیام به Agent اصلی برگرداند. بخش‌های مستقل را ادامه دهد؛ پس از پایان بخش مستقل، نتیجهٔ جزئی و مانع ادامه را ثبت کند. Agent اصلی تصمیم‌های موجود را بازیابی و سؤالِ هنوز لازم را در DECISIONS ثبت کند؛ فقط خودش با کاربر گفتگو کند.
- پس از پاسخ روشن، منشأ و زمان را ثبت کن؛ قرارداد نسخهٔ تازه بگیرد. قبل از اعمال نتیجه، اختیار و تازگی منابع را بررسی کن. نتیجهٔ منسوخ یا تصمیم‌نشده اعمال نمی‌شود. فقط Agent اصلی ثبت نهایی و رویداد تاریخچه را انجام دهد؛ شناسه/نسخه/تلاش و مقصد را ثبت کند تا نتیجه دوباره اعمال نشود. «نتیجه آماده» یا «اعمال‌شده» پایان تسک کاربر را اعلام نمی‌کند.
